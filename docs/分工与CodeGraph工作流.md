## CodeGraph 操作顺序

项目当前已有 `.codegraph/` 索引。使用前先确认索引状态；已有索引时直接复用，不重复初始化，也不安装全球 MCP。

下面的命令参数已通过本机 CLI 的 `--help` 核对：

```bash
cd "/Volumes/My Passport/Project/51mai website clone"

# 1. 确认现有索引；--json 是 status 已确认的输出选项
if [ -d .codegraph ]; then
  codegraph status --json
else
  # 只有 .codegraph 不存在时初始化；-y 和 -v 已确认
  codegraph init -y -v .
fi

# 2. 先用自然语言探索调用关系和相关源码；-p、--max-files 已确认
codegraph explore -p "$PWD" --max-files 8 \
  "定位登录注册、用户中心、订单支付、上游同步和后台权限的入口、调用关系与持久化方式"

# 对一个明确符号查看源码、调用者和被调用者；-p、-f、--offset、--limit 已确认
codegraph node -p "$PWD" -f src/data.ts --offset 1 --limit 80
codegraph node -p "$PWD" LoginPage

# 3. 修改前先看符号影响范围；-p、-d、-j 已确认
codegraph impact -p "$PWD" products -d 2 -j

# 根据变更源码选择受影响的测试；--depth、--quiet 已确认
codegraph affected -p "$PWD" src/data.ts src/App.tsx --depth 5 --quiet

# 4. 完成局部修改并运行相关测试、类型检查和构建
npm test -- --run
npm run typecheck
npm run build

# 5. 修改完成后同步增量索引；sync 的路径是位置参数，--quiet 也已确认
codegraph sync "$PWD"
codegraph status --json
```

`codegraph init -y -v .` 是缺少索引时的条件命令，不应在已有索引上反复运行。工作流中的固定顺序是：使用已有或明确初始化的索引 → `explore`/`node` 定位 → `impact`/`affected` 选择影响范围和测试 → 最小修改 → 测试与构建 → `sync` 增量更新索引。

## 证据边界

### CodeGraph 能证明什么

- 索引中存在的文件、符号、静态源码和调用/依赖关系。
- 修改某个符号可能影响的调用者及可关联测试范围。
- 当前源码结构中的静态关系，帮助减少盲目搜索和无关改动。

### CodeGraph 不能证明什么

- 不能证明某功能在参考分站当前账号、租户或插件开关下已经启用。
- 不能证明某个静态路由或字符串对应的 API 真实可访问、鉴权通过或具有下单/取卡权限。
- 不能证明支付回调、库存、订单状态、卡密交付或后台配置已经真实保存和联动。
- 不能替代浏览器中的当前页面操作、网络请求证据、真实接口文档、自动化测试或生产验收。

### 三类证据必须分开记录

1. **参考站浏览器证据**：实际登录账号能够看到并操作的入口、字段、状态和结果，用于判断当前功能是否启用。
2. **本地源码/测试证据**：仓库中实际存在的实现、测试、类型检查和构建结果，用于判断本地代码现状。
3. **CodeGraph 静态证据**：符号和依赖关系，用于定位和选择影响范围；它不是业务启用证明。

未在参考站或正式接口文档中确认的入口，状态只能记录为“未知/待核实”，不得因为源码、图谱、教程或猜测存在就开始开发。确认后仍须按当前阶段门禁推进。

## 每轮交付格式

局部任务完成后，luna-worker 应报告：

- 已完成：具体文件、功能和范围。
- 修改位置：绝对路径及关键行号/符号。
- 验证结果：实际运行的命令、测试文件数、测试总数、失败数、TypeScript 和 Build 状态。
- 影响范围：`impact`/`affected` 输出所指向的调用者和测试。
- 未完成或待确认：真实接口、参考站行为、外部服务或主代理集成仍缺少的证据。

报告中不得把“页面存在”“静态数据可渲染”“CodeGraph 找到符号”写成“真实业务已完成”。
